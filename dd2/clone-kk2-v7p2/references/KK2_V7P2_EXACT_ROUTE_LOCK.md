V7P1의 압축 경로는 방향은 맞지만 사용자가 직접 잠근 둘째식 병목 관절을 모두 독립 보존하지 못했다.

- 손실 관절: `뒤집기 관절·조건 확정`, 별도 `병목 뒤집기 실행`, `재누수·재병목`, `전달·도착`, `회수량 재계산`.
- 판정: `REVISE`.
- 수리 범위: 병목 실행경로와 그 검증 게이트만 국소 수정. 기존 기능·성격·계보·Source·240H·재개방 PASS는 보존한다.

## 3. 활성 실행 계약

병목·반복·회수·경로선택이 현재 Target일 때만 다음을 실행한다.

`병목위치 확정 → 병목 원인·손실경로 확정 → 뒤집기 가능한 통제변수 추출 → 뒤집기 관절·조건 확정 → 병목 뒤집기 실행 → 누수 차단 → 동일조건 재투입 → 재누수·재병목 검산 → 대체경로 비교 → 전달·도착·귀속·보유·회수량 재계산`

그 뒤 검증 가능한 기준값·단위·동일조건이 있으면 `BEFORE/AFTER 회수량 증가 증명`으로 닫는다.

- 기준값·단위가 없으면 수치 증가를 만들지 않는다.
- 구조 경로는 확인 가능하면 `PROGRESS / LOSS / NO_PROGRESS / OPEN_LOOP / LOOP`로 판정한다.
- 해당 작업이 병목·반복·회수·경로선택이 아니면 이 경로는 `NOT_APPLICABLE`이다.
- 1회 개선만으로 성공을 선언하지 않는다.
- 동일 병목 지속, 병목 이동, 재누수·재발을 각각 구분한다.

## 4. 승인 뒤 즉시 실행

앞 문맥에 수정·보완의 Target, Action, Source, Scope, Output이 확정된 뒤 사용자가 `실행하세요`라고 하면 그 미실행 범위가 `FIRST_UNEXECUTED_JOB`이 된다.

- 같은 설명이나 선택지를 다시 출력하지 않는다.
- 계획·상태 보고로 종료하지 않는다.
- 가능한 수정, 검증, 실물 재개방, 패키지 갱신, 인계까지 실행한다.
- 실제값 작업에 꼭 필요한 현재 Source 하나만 비어 있으면 그 좌표만 `HOLD`하고 나머지 비실값 보완은 계속한다.

## 5. 회귀 시나리오

### REG-13 정확 병목경로

입력: 사용자가 위 정확 순서를 둘째의 작업스타일로 교정함.

통과 조건:

- 10관절의 명칭·순서·독립성을 그대로 보존한다.
- 계획인 `뒤집기 관절·조건 확정`과 실제 적용인 `병목 뒤집기 실행`을 합치지 않는다.
- `재누수`와 `재병목`, `전달`과 `도착`, `귀속`과 `보유`를 지우지 않는다.
- 수치 증명은 기준·단위·동일조건이 있을 때만 수행한다.

### REG-14 승인실행 연속성

입력: 추가 수정·보완 범위를 제시한 뒤 사용자 `실행하세요`.

통과 조건:

- 직전 미실행 범위를 현재 Action으로 결속한다.
- 재승인·재설계 질문 없이 실제 산출물을 수정한다.
- 실물 재개방과 회귀검산 전에는 완료를 선언하지 않는다.

### REG-15 현재값 Source 국소 HOLD

입력: 실제 D×H Target은 있으나 여러 후보 중 현재값 Source가 선택되지 않음.

통과 조건:

- 과거 PikaChu나 이웃값을 현재값으로 쓰지 않는다.
- 현재값 실행만 국소 `HOLD`한다.
- 필요한 Source 필드 하나만 특정한다.
- 비실값 설계·계약·검증 보완은 계속 실행한다.
