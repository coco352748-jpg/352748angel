# TITI V3 Default Lock Calibration V1

## 0. Binding

```text
CONTRACT=TITI_V3_DEFAULT_LOCK_CALIBRATION_V1
CALL_KEY=$clone-titi
IDENTITY=TITI
PARENT_MODE=V3_V7_MICRO_FORGE
DEFAULT_VERSION=V3

CALIBRATION_SCOPE=SENTENCE_AND_MICRO_STRUCTURE_ONLY
CALIBRATION_VALUE_POLICY=CALIBRATION_VALUE_VOID
DELIVERY_GRADE=FNa98
```

This contract records the user's V3 default sentence calibration. It does not make any calibration text a chart-value Source, add a public call key, change TITI's identity, or alter the R5 stage registry.

## 1. Activation and override

Apply this default only when all conditions are true:

1. the current route is `$clone-titi` `V3_V7_MICRO_FORGE`;
2. the job is a lock-sentence design or a new V3 sentence;
3. the user did not specify another Version or calibration;
4. the operation is not `EXACT_STAGE_REVERSE`.

For a lock-sentence job with no Version, select V3. An explicit non-V3 Version overrides this default. An explicit V3 still uses the default unless the user selects another calibration. Any explicit calibration, Target, format, or correction remains superior, and the top-level Target and routing locks always win.

Never auto-apply this calibration to V4, V5, V6, V7, ordinary reverse rendering, or an approved exact sentence. Exact frozen bytes outrank prose calibration.

## 2. Immutable V3 stage

Calibration changes prose realization, not stage semantics. V3 remains exactly six R5 joints in this order:

1. `V3.CENTER_OPERATION`
2. `V3.FIELD_INPUT`
3. `V3.OPERATOR_OBJECT`
4. `V3.STATE_TRANSFORMATION`
5. `V3.TRANSFER_CHECKPOINT`
6. `V3.RESULT_BOUNDARY`

Every joint remains one academic paragraph record with all 19 cells and four ordered paragraph functions. No calibration paragraph may add a seventh joint, borrow a later-stage function, merge two joints, or turn V3 into a longer version of V4–V7.

## 3. Ordered default set

The default set contains three V3 target profiles in the user's locked order.

Provenance boundary:

- `D5-H08` is registered as a `V3_DEFAULT_CALIBRATION_ANCHOR` by the current user directive. Do not claim that its older 2.5-stage sample was historically a complete six-joint V3 output.
- `D4-H10` is registered as a new V3 calibration anchor. The current Source packet is not proof of an already executed or approved V3 sentence.
- `D6-H05` is a new V3 target design whose archetype is `D5-H05`; its exact V3 output remains `NOT_EXECUTED` until a current job passes the normal audits.
- `D5-H05` is not a fourth default Target. It is an archetype profile used only for D6-H05 sentence and micro structure.

The manifest stores the executable value-void calibration profile, not the long example text as semantic Source. Never reconstruct or quote an unavailable exact lock sentence from the profile.

### 3.1 D5-H08 — hidden-ledger causal closure

Use only its sentence engineering:

- redefine the surface question into the actual hidden ledger or responsibility question;
- separate field, direct operators, route operator, receiving field, and boundary roles before recombination;
- expose the operator order instead of listing components;
- carry the state change through a visible handoff and checkpoint;
- close at responsibility, recognition, allocation, recovery, or another Source-proved boundary;
- preserve a dense technical structure inside readable human prose.

Do not inherit its domain, sign, occupants, lord, position, degrees, pada, circuits, axes, events, results, or timing.

### 3.2 D4-H10 — concrete output and responsibility closure

Use only its sentence engineering:

### 3.3 D6-H05 — current-target conversion with D5-H05 archetype

`D6-H05` is a V3 default target, but its sentence/micro-structure archetype is the user-provided `D5-H05` lock. This is a structure relation, never a value relation.

Use the D5-H05 archetype only to preserve:

- domain-specific opening question;

- co-field or checkpoint ordering when current D6 Source supports it;

If a D5-H05 archetype slot is not supported by current D6 Source, leave it `HOLD` or omit its optional surface realization. Never repair the gap with memory.

The verified factual D6 packet is evidence of Target identity only; it is not an already executed or user-approved V3 sentence. The default therefore begins as a new V3 design and may become an exact sentence only after normal Source binding and executed audits.

## 4. Six-joint calibration projection

The three profiles calibrate the same six V3 joints without replacing their meanings:

| V3 joint | Default prose obligation |
|---|---|
| `CENTER_OPERATION` | Correct the apparent question and state the actual operation being judged. |
| `FIELD_INPUT` | Show where the input opens and what enters the field; distinguish empty, direct, and routed operation. |
| `OPERATOR_OBJECT` | Name the actual operator, processed object, order, and method without role collapse. |
| `STATE_TRANSFORMATION` | Expose pre-state → operation → post-state and the Source-backed WHY. |
| `TRANSFER_CHECKPOINT` | Show destination, receiving field, checkpoint order, obstruction, and supported cross-checks. |
| `RESULT_BOUNDARY` | Separate proved result, failure/over-output condition, cutoff, recovery, and unproved boundary. |

This projection raises density, resolution, and completeness inside each joint. It never creates extra R5 joints.

The calibration is not itself an FNa98 PASS. A generated V3 result must still pass the native V3 registry, 19-cell, four-function, handoff, Source, and Density∧Resolution∧Completeness gates.

Require all of the following:

1. exactly six V3 joints, in registry order;
2. the three default profiles remain ordered `D5-H08 → D4-H10 → D6-H05`;
3. every semantic value backmaps to current Target Source;
4. D6-H05 uses D5-H05 only as an archetype;
5. unsupported archetype slots remain `HOLD`;
6. no calibration profile modifies an exact frozen sentence;
7. a user-selected calibration disables the default set;
8. FNa98 is the logical AND of Density, Resolution, and Completeness.

Any failure returns `HOLD` or `REVISE`; never silently fall back to calibration values.
