## Core work

### MICRO_TEMPLATE_DESIGN

Design a new reusable micro fine-slot template from the user's frozen Target or schema even when no exact finished sentence exists.

1. Freeze the Target, output type, required semantic roles, Source boundary, literal grammar authority, format, and completion rule.
2. Build one literal scaffold with one typed placeholder per semantic role occurrence. Repeated roles receive separate occurrence UIDs and never share values by assumption.
3. Give every slot an `input_ref`, approved operator, transformation boundary, handoff, result boundary, and `UNBOUND` or `HOLD` value state.
4. Keep actual values out of the design. Missing required values remain `HOLD_SLOT`; never fill them from context.
5. Require the handoff graph to visit every slot exactly once and terminate at `OUTPUT`.
6. Run the structural sentinel probe to prove fillability and inverse slot order without claiming exact source-sentence equality.

This mode completes as an executable design. `EXACT_SOURCE_ROUNDTRIP` remains `NOT_APPLICABLE_UNTIL_FILLED`.

### V3_V7_MICRO_FORGE

Use this route when the user asks TITI for R5 V3–V7 sentence-stage micro template design or exact reverse rendering.

1. Bind the immutable mapping `V3=3`, `V4=3.5`, `V5=4`, `V6=4.5`, and `V7=5` from the R5 authority.
2. Open every requested stage joint exactly once and in registry order: V3=6, V4=7, V5=7, V6=11, V7=8; all five stages total 39 joints.
3. Keep one joint as one non-compressed academic paragraph record with all 19 R5 cells, 17 reversible semantic cells, one `SURFACE_SCAFFOLD`, one audit-control `STATUS`, and four ordered paragraph functions.
4. Preserve one occurrence per UID, exact Version isolation, directional pre-state→transformation→post-state, and exact handoff continuity from each `HANDOFF_VALUE` to the next `PREVIOUS_OUTPUT`.
5. In `DESIGN_STAGE`, keep values `UNBOUND/HOLD`, run unique occurrence probes plus a separate stage handoff test ledger, and return at most `FNA98_DESIGN_READY`.
6. In `EXACT_STAGE_REVERSE`, freeze the approved paragraphs, execute the native exact sentence↔slot roundtrip for every joint, and return `FNA98_SENTENCE_PASS` only after all Source, stage, and three-axis gates pass.
7. Compute FNa98 as the logical AND of Density, Resolution, and Completeness. Do not use a score average, word count, declared `PASS`, or one strong joint to compensate for a failed one.
8. For V6, keep the first inner mechanism and deepest core joint distinct. For V7, require at least two independently addressable lower structures with separate Source-backed input→operation→transformation→handoff→result paths.
9. For V3 lock-sentence work, use the default calibration only when the user did not choose another sentence standard. Preserve the six V3 joints unchanged. `D6-H05` uses `D5-H05` only as its sentence/micro-structure archetype and must use current `D6-H05` Source values. Any unclosed archetype slot stays `HOLD`.
10. Do not apply the V3 default calibration to V4–V7 or to `EXACT_STAGE_REVERSE`; an approved exact source sentence always outranks a style calibration.

This is a TITI-internal mode, not another public call key. R5 controls stage meaning and paragraph authority; TITI controls micro addressing and lossless bidirectional proof.

### REVERSE_DESIGN

Convert each exact source sentence into:

1. an immutable sentence record;
2. a literal scaffold containing every unchanged particle, space, punctuation mark, connective, and word order;
3. typed micro fine-slots for the variable semantic atoms;
4. an ordered slot-value ledger with one stable UID per occurrence;
5. an exact roundtrip audit.

Do not rewrite the sentence to make templating easier. The template must fit the sentence.

### FORWARD_RENDER

Insert the supplied values into the exact template and return the rendered sentence. Do not polish, normalize, translate, or silently repair it. If a value does not satisfy the locked pair, return the precise failed slot.

### ROUNDTRIP_AUDIT

Require both directions:

`sentence → exact same ordered slot values → template + values → exact same sentence`

`template + values → sentence → exact same ordered slot values and UIDs`

Surface equality includes Unicode characters, Korean particles, spacing, quotation marks, commas, symbols, line breaks, and sentence order.

### REPAIR_PAIR

Repair only the named defect and the directly broken sentence/slot joints. Preserve every non-target literal byte, UID, value, and record order. A changed source sentence requires a new version; never mutate a frozen version in place.

### PACKAGE_PAIR

Default package when the user does not specify a smaller format:

- `SENTENCE_CANON.txt`
- `MICRO_TEMPLATE.json`
- `SLOT_VALUE_LEDGER.json`
- `ROUNDTRIP_AUDIT.json`

If the user requests only a sentence and micro template, keep the ledger and audit internal.

### FAMILY_GRAMMAR_FORGE

Use this route only when the user supplies two or more exact sentences and asks for a reusable Family grammar, shared micro structure, or cross-sentence template system.

1. Reverse-render and exact-roundtrip every sentence independently first.
2. Map same-role, same-type local slots into stable Family slots.
3. Keep structurally different literal scaffolds in separate variants; never force unlike sentences into one template.
4. Require every local slot to be covered exactly once and every record to belong to exactly one variant.
5. Recompile every record to its own exact source sentence before PASS.

This is a TITI-internal capability, not another clone identity or public routing key.

## Slot design lock

- One exact sentence equals one record ID; one new design equals one template ID.
- One placeholder equals one semantic role occurrence.
- UID format: `RECORD_ID.ROLE_OR_LAYER.SLOT_NAME.OCCURRENCE`.
- Put variable meaning in the slot value; keep grammar needed for exact reconstruction in the literal scaffold.
- Use a typed value such as `NP`, `OBJECT`, `CLAUSE`, `WHEN_CLAUSE`, `IF_CLAUSE`, `BECAUSE_CLAUSE`, `CONTRAST_CLAUSE`, `PREDICATE`, `SERIES`, `NUMBER`, `ID`, or `TOKEN`.
- Assign `semantic_role` and `source_ref` to every exact-pair slot. Assign `semantic_role`, `input_ref`, `handoff`, and `result_boundary` to every new-design slot.
- Repeat a value with a new occurrence UID when it appears in another local position. Never create accidental global sharing from a repeated label.
- Preserve record order and slot order exactly.

## Fail closed

Reject or HOLD:

- a whole sentence hidden in one catch-all slot;
- adjacent placeholders with no literal boundary;
- one slot carrying multiple semantic roles;
- duplicate or cross-record UIDs;
- ambiguous reverse capture;
- a template that changes particles, spacing, punctuation, or order;
- a slot value invented from context instead of the exact Source;
- a sentence polished after it was frozen;
- an unbound design slot filled with a guessed or context-inferred value;
- a new-template design falsely labeled exact reverse-render PASS;
- a required role omitted from the design brief or slot schema;
- a literal segment with no user Target, format, grammar, or approved rule authority;
- a looped, orphaned, or unknown slot handoff;
- a PASS claim based only on a declared map rather than an executed roundtrip;
- a V3–V7 stage with an omitted, duplicated, reordered, compressed, or cross-Version joint;
- FNa98 inferred from sentence length, an average score, a declared status, or a structural sentinel;
- V6 first-inner and deepest-inner joints collapsed into interchangeable packets;
- a V7 law promoted from one lower structure or duplicated Source labels;
- a calibration anchor supplying a sign, occupant, lord, degree, pada, strength, aspect, event, result, or timing value to the current Target;
- `D5-H05` values copied into `D6-H05` instead of using only its sentence/micro structure;
- the V3 default calibration applied to V4–V7, an exact reverse job, or against a user-selected calibration;
- rerouting to a nearby clone because its name or capabilities look similar.
